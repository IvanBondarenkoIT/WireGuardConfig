# Railway WireGuard Limitation

## Проблема

При попытке запустить WireGuard клиент в Railway контейнере получена ошибка:

**** The wireguard module is not active. If you believe that your kernel should have wireguard support already, make sure that it is activated via modprobe! ****


## Причина

Railway не позволяет запускать WireGuard как VPN клиент потому что:

1. **Нет доступа к ядру Linux** - контейнеры не имеют `CAP_NET_ADMIN` привилегий
2. **Нет модуля WireGuard в ядре** - Railway использует ограниченное ядро
3. **Нет возможности создавать сетевые интерфейсы** - требуется повышенный уровень доступа

## Попытка

- **Дата**: 2026-03-19
- **Сервис**: wireguard-zVvj (ID: fa37cf69-de36-4285-8599-a19b335c0834)
- **Deployment**: 094dc7cd-243e-4097-9775-1803a6fde9b1
- **Статус**: Online но WireGuard модуль не активен
- **Конфиг**: Dockerfile и entrypoint.sh готовы, переменная WG0_CONF установлена

## Решение

Нужно использовать альтернативный подход:

### Вариант 1: OpenVPN (если доступен)
- Может работать в контейнере без повышенных привилегий
- Требуется `.ovpn` конфиг файл

### Вариант 2: HTTP/HTTPS Прокси
- Создать простой прокси-сервер на вашем сервере
- Railway подключается к прокси через HTTPS
- Самый простой и надежный вариант

### Вариант 3: Обратный туннель (SSH/Reverse Proxy)
- Использовать SSH туннель или reverse proxy
- Требует дополнительной настройки на сервере

## Рекомендация

**Вариант 2 (HTTP/HTTPS Прокси)** - самый простой и надежный для Railway.

Нужно:
1. На сервере 178.63.72.227 создать простой HTTP прокси
2. Railway подключается к прокси через HTTPS
3. Прокси туннелирует запросы к Firebird DB
